# DL 08 — Диагностика обучения

## 1. Зачем диагностировать обучение?

Две главные проблемы при обучении нейронных сетей:

| Проблема | Симптом | Что делать |
|---|---|---|
| **Underfitting** | Train loss высокий | Увеличить модель, уменьшить регуляризацию |
| **Overfitting** | Train loss низкий, val loss высокий | Добавить регуляризацию, больше данных |
| **Не сходится** | Loss не уменьшается | Поменять LR, инициализацию, оптимизатор |
| **Leakage** | Val loss подозрительно низкий | Проверить preprocessing, shuffle |

---

## 2. Переобучение (Overfitting)

### Что это такое?
Модель **запоминает** обучающие данные вместо обобщения.

### График:

```
Loss
 ^
 |                      VAL (начинает расти)
 |    ╱╲   ╱╲
 |   ╱  ╲ ╱  ╲
 |  ╱    ╲╱    ╲
 | ╱             ╲╲
 |╱╲╱╲╱╲╱╲╱╲╱╲╱╲ TRAIN (продолжает падать)
 └──────────────────→ Epoch
```

- **Точка расхождения** — момент, когда модель начинает переобучаться.
- **Чем больше gap между train и val**, тем сильнее переобучение.

### Признаки:
1. Train loss → 0, val loss растёт
2. Train accuracy ~100%, val accuracy падает
3. Модель уверена в ошибочных предсказаниях (высокие softmax scores для неверных ответов)

### Как бороться:
| Метод | Эффект |
|---|---|
| Увеличить датасет / аугментации | Больше разнообразия |
| Уменьшить размер модели | Меньше ёмкость |
| [[DL 06 - Стабилизация и регуляризация|Weight decay]] | Штраф за сложность |
| [[DL 06 - Стабилизация и регуляризация|Dropout]] | Коадаптация нейронов |
| Early stopping | Остановка в лучшей точке |
| Label smoothing | Меньше overconfidence |

## 3. Tiny Overfit Test — проверка способности учиться

**Перед полноценным обучением**: убедиться, что модель может **выучить** маленький поднабор данных.

### Процедура:
1. Берём **1-5 батчей** данных из train (например, 32-128 примеров)
2. Обучаем **до нулевого loss**
3. Если модель **не может** переобучить tiny subset → проблема в архитектуре или коде

### Что проверяем:

| Результат | Вердикт |
|---|---|
| Loss → 0, accuracy → 100% за несколько шагов | ✅ Модель работает |
| Loss не падает, accuracy не растёт | ❌ Ошибка: loss, оптимизатор, архитектура |
| Loss падает медленно | ❌ Слишком низкий LR, плохая инициализация |
| Loss → NaN | ❌ Взрыв градиента (клиппинг/инициализация) |

### Почему это важно:
- Отсекает **ошибки в коде** до того, как начнёшь долгое обучение
- Проверяет, достаточно ли ёмкости у модели
- Если модель не может выучить 32 примера — она точно не выучит 32 000

## 4. Train/Validation Curves — анализ кривых обучения

### 4.1. Типичные паттерны:

```
Loss                              Loss
 ^                                 ^
 |╱╲      ← underfitting          |    ╱╲     ← хорошее обучение
 |   ╲                             |   ╱  ╲
 |    ╲╱╲╱╲╱                      |  ╱    ╲
 |         ╲                       | ╱      ╲╱╲╱╲╱╲
 └──────→ Epoch                    └────────────→ Epoch
```

### 4.2. Интерпретация:

| Вид кривых | Диагноз | Решение |
|---|---|---|
| Train и val loss оба высокие, gap мал | **Underfitting** | Больше модель, меньше регуляризация, больше эпох |
| Train loss низкий, val loss растёт | **Overfitting** | Регуляризация, аугментации, early stopping |
| Train loss падает, val loss не падает | **Недостаточно данных** или **data mismatch** | Проверить распределение val |
| Train loss = val loss = константа | **Не учится** | Проверить код, LR, инициализацию |
| Оба loss снижаются синхронно | **Идеально** (но редкое счастье) | Продолжать |

### 4.3. Как строить:

```python
# После каждой эпохи:
train_losses.append(train_loss / len(train_loader))
val_losses.append(val_loss / len(val_loader))

# Визуализация
import matplotlib.pyplot as plt
plt.plot(train_losses, label='Train')
plt.plot(val_losses, label='Validation')
plt.legend()
plt.xlabel('Epoch')
plt.ylabel('Loss')
plt.show()
```

## 5. Data Leakage (Утечка данных)

Самая опасная проблема: **информация из test/val "просачивается" в train** → валидационные метрики завышены.

### Виды leakage:

| Тип | Пример | Последствия |
|---|---|---|
| **Preprocessing leakage** | Normalize val на mean/std всего датасета | Val с похожим распределением → завышенная accuracy |
| **Temporal leakage** | Перемешать временные ряды целиком | Модель видит "будущее" |
| **Duplicate leakage** | Одинаковые изображения в train и val | Искусственная высокая accuracy |
| **Feature leakage** | Признак, который не будет доступен на инференсе | Невалидная модель |
| **Target leakage** | Признак, косвенно содержащий ответ | Идеальный, но бесполезный результат |

### Как избежать:

```python
# 1. Сначала split, потом preprocessing!

from sklearn.model_selection import train_test_split

X_train, X_test, y_train, y_test = train_test_split(X, y)

# 2. Среднее и std — ТОЛЬКО из train
mean = X_train.mean(0)
std = X_train.std(0)

X_train = (X_train - mean) / std
X_test = (X_test - mean) / std   # используем mean/std train!
```

### Проверка на leakage:
- Если val accuracy > 95% на сыром baseline — подозрительно
- Сделать shuffle меток на val → если accuracy не падает → **definite leakage**

## 6. Подбор гиперпараметров (Hyperparameter Tuning)

### Что настраиваем (в порядке важности):

1. **Learning rate** — самый важный (ищи на логарифмической шкале)
2. **Batch size** — влияет на стабильность + обобщение
3. **Архитектура** — глубина, ширина, тип слоёв
4. **Weight decay** — от $10^{-5}$ до $10^{-1}$
5. **Dropout rate** — 0.1–0.5
6. **Optimizer** — AdamW обычно, SGD + Momentum для CV

### Стратегии поиска:

| Метод | Описание | Плюсы | Минусы |
|---|---|---|---|
| **Grid Search** | Все комбинации | Просто | Экспоненциальный рост |
| **Random Search** | Случайные точки | Эффективнее Grid | Не гарантирует coverage |
| [[DL 05 - Оптимизация|**Bayesian Opt**]] | Probabilistic model (GP) | Эффективен | Сложный, Sequential |
| **Population Based** | Эволюция гиперпараметров | Распараллеливается | Дорого |

### Важные принципы:

**Log-scale для непрерывных гиперпараметров:**
```python
lr = 10 ** uniform(-4, -1)          # от 1e-4 до 1e-1
weight_decay = 10 ** uniform(-5, -2) # от 1e-5 до 1e-2
```

**Начинайте с малого:**
1. Tiny overfit test → убедиться, что учится
2. Baseline с LR finder → оптимальный LR
3. Обучить 10-20 эпох → понять динамику
4. Полное обучение с tuning

### Learning Rate Finder:

```python
# Классический подход (из fastai)
model.train()
optimizer = optim.SGD(model.parameters(), lr=1e-7)
lrs, losses = [], []

for batch in loader:
    loss = criterion(model(batch[0]), batch[1])
    loss.backward()
    optimizer.step()
    
    lrs.append(optimizer.param_groups[0]['lr'])
    losses.append(loss.item())
    
    # Увеличиваем LR экспоненциально
    optimizer.param_groups[0]['lr'] *= 1.1
    
    if optimizer.param_groups[0]['lr'] > 10:
        break

# Берём LR на минимуме loss (или в 10 раз меньше)
```

## 7. Чеклист диагностики при проблемах

```
❌ Loss = NaN → Gradient clipping, снизить LR, проверить инициализацию
❌ Loss не падает → Tiny overfit test, сменить оптимизатор
❌ Train loss 0, val плохо → Early stopping, Dropout, Weight decay
❌ Val accuracy > train → Leakage (shuffle val targets!)
❌ Колебания (осцилляции) → Уменьшить LR, увеличить batch size
❌ Медленная сходимость → Увеличить LR, momentum, better init
❌ Валидация не улучшается → Data mismatch (проверить, что val из того же распределения)
```

---

## 8. Резюме

- **Overfitting**: train << val loss → регуляризация, early stopping
- **Tiny overfit test**: критический первый шаг перед любым обучением
- **Кривые обучения**: основной инструмент визуальной диагностики
- **Data leakage**: главная причина ложных успехов (split до preprocessing!)
- **Hyperparameter tuning**: LR → batch size → weight decay → dropout
- **LR finder**: быстрый способ найти хороший LR
