## 1. In-Context Learning (ICL)

### Определение

ICL — способность [[DL 36 - GPT|LLM]] решать задачи на основе **демонстраций** (примеров), включённых в промпт, **без обновления весов**.

### Формально

Модель получает контекст:

$$
C = [ (x_1, y_1), (x_2, y_2), \dots, (x_k, y_k), x_{\text{query}} ]
$$

и генерирует $y_{\text{pred}}$:

$$
y_{\text{pred}} = \arg\max P_{\text{LLM}}(y \mid C)
$$

**Никакого градиентного шага** — модель использует только forward pass.

### Типы ICL по числу примеров

| Тип | K (примеров) | Пример |
|---|---|---|
| Zero-shot | 0 | "Переведи на французский: Hello" |
| One-shot | 1 | "Англ: Hello → Фр: Bonjour. Англ: Cat →" |
| Few-shot | 2+ | 3–10 демонстраций |

### Механизм ICL (гипотезы)

1. **Pattern matching:** Модель извлекает паттерн из контекста
2. **Скрытое обучение (meta-learning):** ICL — проявление meta-learning способностей, где контекст — это "support set"
3. **Функциональная спецификация:** Примеры задают функцию отображения вход→выход
4. **Task recognition:** Модель узнаёт задачу из примеров и применяет знания из pre-training

## 2. Few-Shot Prompting

### Структура промпта

```
Задача: Переведи английские слова на французский.

Англ: dog → Фр: chien
Англ: house → Фр: maison
Англ: book → Фр: livre
Англ: cat →
```

### Важные факторы

| Фактор | Влияние |
|---|---|
| Количество примеров | Больше → лучше (до насыщения ~10–20) |
| Порядок примеров | Чувствителен — похожие к query лучше ближе |
| Релевантность | Примеры из того же домена → лучше |
| Разнообразие | Покрытие разных случаев → лучше |
| Метки (labels) | Правильные метки критичны |

### Выбор примеров (Retrieval-Augmented ICL)

- Случайный выбор — baseline
- **kNN-поиск** среди обучающих примеров по эмбеддингам
- Кластеризация — выбираем репрезентативные примеры
- **Diversity-based** — покрываем разные подзадачи

## 3. Chain-of-Thought (CoT) Prompting — Wei et al., 2022

### Идея

Вместо прямого ответа модель генерирует **цепочку рассуждений** (промежуточные шаги).

### Пример

**Standard prompt:**
```
Q: У Роджера 5 теннисных мячей. Он покупает ещё 2 банки по 3 мяча. Сколько всего?

A: 11
```

**CoT prompt:**
```
Q: У Роджера 5 теннисных мячей. Он покупает ещё 2 банки по 3 мяча. Сколько всего?

A: У Роджера изначально 5 мячей.
   Покупает 2 банки по 3 мяча = 2 × 3 = 6 мячей.
   5 + 6 = 11.
   Ответ: 11
```

### Chain-of-Thought prompting (few-shot)

Демонстрации содержат полную цепочку рассуждений + ответ:

```
Q: {question_1}
A: {chain_of_thought_1} Ответ: {answer_1}

Q: {question_2}
A: {chain_of_thought_2} Ответ: {answer_2}

Q: {query}
A:
```

### Zero-Shot CoT — Kojima et al., 2022

Достаточно добавить магическую фразу **"Let's think step by step"** (или "Давайте рассуждать по шагам") после вопроса:

```
Q: {question}
A: Let's think step by step.
```

#### Этапы Zero-shot CoT

1. **Raisonnement** (рассуждение): модель генерирует CoT
2. **Extraction** (извлечение ответа): второй промпт "Therefore, the answer is" или извлечение последнего предложения

#### Эффективность

- GSM8K (математика): ~18% → ~70% (GPT-3, 175B)
- MultiArith: ~17% → ~79%
- Эффект проявляется на моделях ≥100B параметров

## 4. Разновидности CoT

### Self-Consistency — Wang et al., 2022

Генерируется несколько CoT путей → ответ определяется **мажоритарным голосованием**:

$$
\hat{y} = \arg\max_y \sum_{i=1}^N \mathbb{I}\left[\text{extract}(y^{(i)}) = y\right]
$$

где $y^{(i)}$ — ответ из $i$-го CoT-пасса.

- Улучшает точность на 5–15%
- Компенсирует стохастичность модели
- Не требует дополнительного обучения

### Tree-of-Thoughts (ToT) — Yao et al., 2023

- CoT — линейная цепочка
- ToT — дерево рассуждений: модель генерирует несколько вариантов на каждом шаге
- Используется BFS/DFS с оценкой (value function) каждого узла

### Self-Ask / Step-Back

- Модель сама формулирует подвопросы
- **Step-Back Prompting:** перед ответом модель задаёт более общий вопрос

## 5. Reasoning Prompts — продвинутые техники

### Least-to-Most Prompting

1. Декомпозиция задачи на подзадачи
2. Решение по порядку, используя предыдущие ответы

### Program-of-Thoughts (PoT)

Генерация кода вместо текстовых рассуждений:

```
Q: {math_question}
A: Let's write Python:
```python
# code here
```
```

### Logic-of-Thought (LoT)

Использование формальной логики (Prolog/SMT) для рассуждений.

### Contrastive CoT

Демонстрация как правильных, так и неправильных рассуждений.

## 6. Ограничения промптового подхода

### 1. Зависимость от промпт-инжиниринга

- Небольшие изменения формулировки сильно влияют на качество
- Чувствительность к порядку примеров
- "Охота за промптами" — нет гарантии оптимальности

### 2. Ограниченная длина контекста

- Старые модели: 512–2048 токенов
- Современные: 4K–128K, но качество падает на длинном контексте ([[DL 45 - RAG, длинный контекст и агенты|Lost in the Middle]])
- CoT потребляет много токенов в промпте

### 3. Отсутствие гарантий

- Модель не "знает", когда она не знает (overconfidence)
- Галлюцинации — генерация правдоподобной неправды
- Смещение (bias) из тренировочных данных

### 4. Вычислительная стоимость

- Каждый запрос — полный forward pass для всей последовательности
- Self-consistency требует N прогонов (дорого)
- CoT генерирует в 3–10× больше токенов, чем прямой ответ

### 5. Невозможность обновления знаний

- ICL не меняет веса — знания ограничены pre-training cutoff
- Для новых знаний нужен [[DL 45 - RAG, длинный контекст и агенты|RAG]] или [[DL 38 - Дообучение LLM|fine-tuning]]

### 6. Сложные рассуждения

- CoT работает на простых задачах, но fails на multi-hop reasoning
- Модель может неявно "срезать углы" (shortcut reasoning)
- Арифметические ошибки остаются

### 7. Отсутствие обратной связи

- Нет итеративного уточнения (если не реализовано через агентский цикл)
- Single-pass → нет возможности исправить ошибку

## 7. Сравнительная таблица методов

| Метод | Нужны примеры | Качество | Стоимость (токены) | Сложность |
|---|---|---|---|---|
| Zero-shot | Нет | Low | Низкая | Нулевая |
| Few-shot | Да (3–10) | Medium | Средняя | Низкая |
| CoT few-shot | Да (3–10) | High | Высокая (2–5×) | Низкая |
| Zero-shot CoT | Нет | Medium-High | Средняя | Нулевая |
| Self-consistency | Нет/Да | Very High | Очень высокая (N×) | Низкая |
| ToT | Нет | Highest | Максимальная | Высокая |
| PoT | Нет/Да | High | Зависит | Средняя |

---

## 8. Когда какой метод использовать

| Задача | Рекомендуемый подход |
|---|---|
| Классификация (сентимент, интенты) | Zero-shot или Few-shot |
| Извлечение информации | Few-shot с примерами |
| Математические задачи | Zero-shot CoT или Self-consistency |
| Логические рассуждения | CoT Few-shot |
| Кодогенерация | Few-shot + PoT |
| Многошаговые задачи (агенты) | ReAct (Combination of CoT + Actions) |
| Критические приложения | Self-consistency + ToT |

---

## 9. Ключевые выводы

1. **ICL** — мощный механизм адаптации LLM без обучения, но ограничен контекстом и не обновляет знания
2. **CoT** — прорыв в рассуждениях, особенно эффективен на моделях ≥100B
3. **Zero-shot CoT** ("Let's think step by step") — простейший способ улучшить рассуждения
4. **Self-consistency** — эффективное повышение качества через ансамблирование
5. Промптовый подход **не заменяет** [[DL 38 - Дообучение LLM|fine-tuning]] для глубокой адаптации
6. Главные ограничения: длина контекста, галлюцинации, стоимость, отсутствие гарантий
