# 31. Токенизация текста

## 1. Определение

**Токенизация:** разбиение текста на минимальные единицы (токены), которые подаются на вход модели.

**Зачем:** нейронные сети работают с числами, не с текстом. Токены преобразуются в индексы словаря.

---

## 2. Уровни токенизации

### 2.1 Word-level (потокенная, пословная)

**Принцип:** каждое уникальное слово — отдельный токен.

**Пример:**
```
"I love cats" → ["I", "love", "cats"]
```

**Преимущества:**
- Интуитивно понятно.
- Высокая семантическая ёмкость (один токен = одно слово).

**Недостатки:**
- **Размер словаря:** $|V| \sim 50\text{k} - 1\text{M}$ (английский ~500k слов).
- **OOV (Out-of-Vocabulary):** незнакомые слова = неизвестный токен `[UNK]`.
  - "Cats" в обучающем корпусе есть, а "kittens" — нет → `[UNK]`.
- **Морфология игнорируется:** "run", "running", "ran" — разные токены, хотя семантически связаны.
- **Редкие слова:** большая часть словаря встречается 1-2 раза (Zipf's law).

### 2.2 Char-level (посимвольная)

**Принцип:** каждый символ (буква, цифра, пунктуация) — отдельный токен.

**Пример:**
```
"cat" → ["c", "a", "t"]
```

**Преимущества:**
- **Нет OOV:** любое слово можно представить последовательностью символов.
- **Морфология доступна:** "running" → r-u-n-n-i-n-g (суффикс -ing виден).
- **Маленький словарь:** ~100-200 символов (буквы + цифры + пунктуация).

**Недостатки:**
- **Длинные последовательности:** длина последовательности в 5-10 раз больше (слово из 5 символов = 5 токенов вместо 1).
- **Сложнее учить семантику:** модель должна сначала понять, что "c-a-t" — это слово.
- **Вычислительно дорого:** $O(L^2)$ для self-attention при длине $L$.
- **Потеря информации о слове:** модель видит символы, не зная границ слов.

### 2.3 Subword (подсловная токенизация) — золотая середина

**Принцип:** токены — это части слов (чаще всего): частые слова — целые токены, редкие — разбиваются на подслова.

**Пример (BPE):**
```
"unhappiness" → ["un", "happiness"]
"running" → ["running"]  (частотное слово — целый токен)
"kittens" → ["kitt", "en", "s"]  (редкое — разбивается)
```

**Баланс:**
- Словарь разумного размера: 30k-100k токенов.
- Нет OOV (любое слово можно собрать из подслов).
- Длина последовательности умеренная: слово = 1-3 токена.

## 3. BPE (Byte Pair Encoding, Sennrich et al., 2016)

### 3.1 История

Изначально — алгоритм сжатия данных (Gage, 1994). Sennrich адаптировал для NLP.

### 3.2 Алгоритм

1. **Инициализация:** словарь из всех символов (букв) + специальные токены (`[UNK]`, `[PAD]`).

2. **Препроцессинг:** разбить каждое слово на символы с маркером конца слова:
   ```
   "cat" → ["c", "a", "t</w>"]
   "cats" → ["c", "a", "t", "s</w>"]
   ```

3. **Повторять $K$ раз (желаемый размер словаря):**
   - Подсчитать все пары соседних символов/подслов.
   - Найти самую частую пару.
   - Объединить её в новый подсловный токен.
   - Добавить объединение в словарь.

4. **Итог:** $K$ добавленных подслов + исходные символы = финальный словарь.

### 3.3 Пример

**Шаг 1:** "c", "a", "t" → пара ("a", "t") самая частая → merged → ["c", "at"]
**Шаг 2:** ("c", "at") → merged → ["cat"]

### 3.4 Токенизация новым текстом (inference)

1. Разбить на символы.
2. Последовательно объединять пары (используя обученные merge rules).

**Жадный алгоритм:** всегда берём самое длинное совпадение слева направо.

### 3.5 Преимущества BPE

- **Языконезависимость:** работает для любого языка.
- **Компактный словарь:** типично 32k-50k токенов.
- **Нет OOV:** любое слово разбивается до символов (которые есть в словаре).
- **Частые слова = 1 токен:** эффективно.

### 3.6 Недостатки BPE

- **Жадная токенизация:** может давать неоптимальное разбиение.
- **Нестабильность:** для слов, не встреченных в обучении, разбиение может быть разным.
- **Не учитывает морфологию:** "un" + "happiness" — ок, но "unhappiness" могло бы быть "unhappy" + "ness".

## 4. WordPiece (Schuster & Nakajima, 2012; популяризирован BERT)

### 4.1 Отличие от BPE

**BPE:** объединяет **самые частые пары**.
**WordPiece:** объединяет пары, которые **максимизируют правдоподобие** (likelihood) данных.

### 4.2 Формула

Выбирается пара $(a, b)$, максимизирующая:
$$
\text{score}(a, b) = \frac{\text{count}(ab)}{\text{count}(a) \cdot \text{count}(b)}
$$

(увеличение likelihood тренировочных данных)

### 4.3 Характерные черты

- **Префикс ##:** WordPiece маркирует подслова, не являющиеся началом слова: `"playing" → ["play", "##ing"]`.
- **Более "морфологический":** даёт более чистые морфемы, чем BPE.
- **Используется в BERT:** словарь 30k токенов.

### 4.4 Сравнение BPE vs WordPiece

| Характеристика | BPE | WordPiece |
|---|---|---|
| **Метрика объединения** | Частота пары | $\frac{\text{count}(ab)}{\text{count}(a)\text{count}(b)}$ |
| **Маркер подслова** | `</w>` (конец слова) или `##` | `##` (не начало слова) |
| **Популярность** | GPT-2, GPT-3, RoBERTa, XLM-R | BERT, DistilBERT, ALBERT |
| **Сложность** | Проще | Немного сложнее |
| **Морфология** | Чуть хуже | Чуть лучше |

## 5. Byte-level BPE (BBPE / Byte-level BPE, с GPT-2)

### 5.1 Мотивация

Даже символьный словарь имеет OOV для rare Unicode-символов (эмодзи, иероглифы).

**Решение:** работать на уровне **байтов** (256 значений).

### 5.2 Алгоритм

- Каждый Unicode-символ кодируется в 1-4 байта (UTF-8).
- Применяем BPE к последовательности байтов.
- Словарь: 256 байтовых токенов + merged пары.

### 5.3 Преимущества

- **Полное покрытие Unicode:** любой текст может быть закодирован (даже эмодзи 🎉, иероглифы 汉字).
- **Любой язык:** не нужно думать о языковой токенизации.
- **Универсальность:** одна токенизация для всего.

### 5.4 Недостатки

- **Длинные последовательности:** Unicode-символы становятся 1-4 токенами вместо 1.
- **Неэффективно для ASCII-текста:** "cat" → 3 байта = 3 токена в худшем случае.
- **Потеря семантики подслова:** модель видит байты, не части слов.

### 5.5 Кто использует

- **GPT-2/GPT-3:** BBPE со словарём 50k токенов.
- **RoBERTa:** BPE на уровне символов (не байтов).
- **Modern LLM:** почти все используют byte-level BPE (Llama 2, GPT-4, Claude).

## 6. Другие методы токенизации

### 6.1 SentencePiece (Kudo & Richardson, 2018)

**Идея:** токенизация до применения NLP pipeline — **сырой текст** → токены.

**Особенности:**
- Работает на уровне Unicode (не требует pre-tokenized whitespace).
- Реализует BPE и unigram language model.
- Обработка пробелов: пробел → специальный символ `_` (underscore).
- **Используется в:** T5, ALBERT, XLNet, Llama.

**Преимущество:** не требует предварительной токенизации на слова (whitespace splitting).

### 6.2 Unigram Language Model (Kudo, 2018)

**Альтернатива BPE:**
1. Начать с большого словаря (все возможные подслова).
2. Итеративно удалять подслова, минимизирующие потерю likelihood.
3. Итог: оптимальный словарь заданного размера.

**Prefered для:** SentencePiece (как опция вместо BPE).

## 7. Unicode/UTF-8 и токенизация

### 7.1 Проблема

ASCII = 128 символов — 1 байт на символ.
Unicode = > 1М символов — в UTF-8 1-4 байта на символ.

**Символьная токенизация:** символ — это Unicode code point, но code point не совпадает с байтом для многих символов.

**Байтовая токенизация:** работаем с UTF-8 байтами — 256 токенов, полное покрытие.

### 7.2 Выбор

| Задача | Рекомендуемая токенизация |
|---|---|
| Английский текст | WordPiece / BPE (словарь 30k-50k) |
| Многоязычный | SentencePiece (Unigram) |
| Эмодзи/спецсимволы | Byte-level BPE |
| Код (code) | Byte-level BPE |
| Азиатские языки (без пробелов) | SentencePiece |
