# DL 09 — Изображение как тензор, мотивация CNN

## 1. Изображение как тензор

Цифровое изображение — это **трёхмерный тензор**:

$$x \in \mathbb{R}^{H \times W \times C}$$

- $H$ — высота (height) в пикселях
- $W$ — ширина (width) в пикселях
- $C$ — число каналов (channels)

### Типичные форматы:

| Тип изображения | Размерность | Каналы |
|---|---|---|
| Чёрно-белое (Grayscale) | $H \times W \times 1$ | 1 (интенсивность) |
| Цветное (RGB) | $H \times W \times 3$ | 3 (Red, Green, Blue) |
| RGBA | $H \times W \times 4$ | 4 (+ Alpha/прозрачность) |
| Мультиспектральное | $H \times W \times C$ | C (до десятков каналов) |
| Гиперспектральное | $H \times W \times C$ | C (сотни каналов) |

### В PyTorch (CHW vs HWC):

PyTorch использует формат **CHW** (Channel-first): $(C, H, W)$ для совместимости с операциями свёртки.

```python
# Форма тензора в PyTorch
image = torch.randn(3, 224, 224)    # RGB, 224x224
batch = torch.randn(32, 3, 224, 224) # батч из 32 изображений
```

## 2. Каждый пиксель — число

Для 8-битного изображения: $0 \leq x_{i,j,c} \leq 255$.

На практике обычно нормализуют:
- К [0, 1]: $x / 255$
- К [-1, 1]: $(x / 255) \times 2 - 1$
- Стандартизация: $(x - \mu) / \sigma$ (например, ImageNet: $\mu=[0.485, 0.456, 0.406]$, $\sigma=[0.229, 0.224, 0.225]$)

```python
from torchvision import transforms

transform = transforms.Compose([
    transforms.ToTensor(),                    # HWC → CHW, [0,255] → [0,1]
    transforms.Normalize(                     # стандартизация
        mean=[0.485, 0.456, 0.406],
        std=[0.229, 0.224, 0.225]
    )
])
```

## 3. Почему полносвязный слой (FC) плох для изображений?

Рассмотрим изображение $224 \times 224 \times 3$ = **150 528 чисел**.

Полносвязный слой: $y = Wx + b$

$$W \in \mathbb{R}^{d_{out} \times 150528}$$

Если $d_{out} = 4096$:

$$\text{Параметров} = 4096 \times 150528 \approx 616 \text{ МИЛЛИОНОВ!}$$

### Три фундаментальные проблемы FC для CV → решение в [[DL 10 - Операция свертки|свёртке]]:

| Проблема | Описание | Почему плохо |
|---|---|---|
| **Огромное число параметров** | Каждый пиксель соединён с каждым нейроном | Переобучение, нехватка памяти |
| **Игнорирование структуры** | Пиксели — плоский вектор, теряется 2D-структура | Модель не знает про расстояния, рёбра |
| **Отсутствие инвариантности** | Сдвиг на 1px → полностью новый вход | Нет устойчивости к трансляциям |
| **No weight sharing** | Каждый регион изображения учится отдельно | Неэффективное использование данных |

### Иллюстрация:

```
FC слой:
        ██ ██ ██    ┌─ w_{1,1}  w_{1,2}  ... ─┐
        ██ ██ ██    │  w_{2,1}  w_{2,2}  ...  │
        ██ ██ ██ ──│  ...                     │──→ нейрон
                    └─ ...                     ┘
                    150528 входов → 616M весов

CNN слой:
        ██ ██ ██    ┌─ w_{1,1}  w_{1,2} ─┐
        ██ ██ ██    │  w_{2,1}  w_{2,2}  │──→ feature map
        ██ ██ ██    └─ w_{3,1}  w_{3,2} ─┘
                    9 весов (ядро 3×3)!
```

## 4. Что нужно для Computer Vision?

### 4.1. Использование 2D-структуры
Пиксели рядом — семантически связаны. Модель должна использовать **локальность** (соседние пиксели образуют рёбра, текстуры).

### 4.2. Трансляционная эквивариантность (Translation Equivariance)
Если сдвинуть объект на изображении — модель должна найти его на новом месте теми же детекторами.

### 4.3. Иерархия признаков
- Низкий уровень: края, углы, цветовые пятна
- Средний уровень: текстуры, формы
- Высокий уровень: части объектов, целые объекты

### 4.4. Weight Sharing (разделение весов)
Один и тот же детектор признаков (ядро) применяется ко всему изображению → **параметрическая эффективность**.

### 4.5. Устойчивость к пространственным трансформациям
- Перевод (translation)
- Масштаб (scale)
- Поворот (rotation)

## 5. Решение: [[DL 11 - Базовая CNN|CNN (Convolutional Neural Network)]]

CNN решает все проблемы FC:

| Требование | Реализация в CNN |
|---|---|
| **2D-структура** | Свёртка работает с 2D-областями (patch) |
| **Локальность** | Ядро свёртки маленькое (3×3, 5×5) |
| **Weight Sharing** | Одно ядро скользит по всему изображению |
| **Параметрическая эффективность** | 3×3 ядро = 9 параметров (не 150K) |
| **Трансляционная эквивариантность** | Свёртка эквивариантна к сдвигу |
| **Иерархия** | Stacking свёрточных слоёв |
| **Понижение размерности** | Pooling/strided convolution |

### Сравнение параметров: FC vs CNN

| Слой | Вход | Выход | Параметров |
|---|---|---|---|
| FC | 150528 | 4096 | ~616M |
| Conv 3×3 (64 канала) | $3 \times 224 \times 224$ | $64 \times 224 \times 224$ | $3 \times 3 \times 3 \times 64 + 64 \approx 1.7K$ |

**Разница в ~360 000 раз!**

---

## 6. Свёртка как "скользящее окно"

Базовая идея: маленькое ядро (kernel) сканирует изображение, вычисляя скалярное произведение:

$$y[i, j] = \sum_{m} \sum_{n} x[i+m, j+n] \cdot w[m, n]$$

- Ядро **разделяется** по всему изображению (weight sharing)
- Локальность: ядро видит только небольшую окрестность
- Детектирует один тип признака (ребро, текстуру)

---

## 7. Резюме

- **Изображение = 3D тензор** $(H, W, C)$.
- **FC слой не подходит**: ~600M параметров для 224×224 RGB, игнорирует 2D-структуру.
- **Что нужно CV**: локальность, weight sharing, трансляционная эквивариантность, иерархия.
- **CNN = ответ**: маленькие ядра, скользящие по изображению, с разделением весов.
- Параметров в свёртке: **~1.7K** vs **~616M** у FC.
