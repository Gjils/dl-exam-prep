## 1. Full Fine-Tuning (FFT)

**Суть:** Все параметры предобученной модели дообучаются на целевом датасете.

### Процесс

1. Берём предобученную [[DL 36 - GPT|LLM]] с параметрами $\theta_{\text{pretrained}}$.
2. Обучаем на целевом датасете $\mathcal{D} = \{(x_i, y_i)\}$.
3. Обновляем **все** $\theta$: $\theta \leftarrow \theta - \eta \nabla_\theta \mathcal{L}(\theta; \mathcal{D})$.

### Особенности

| Характеристика                  | Значение                                                    |
| ------------------------------- | ----------------------------------------------------------- |
| Количество обучаемых параметров | $\theta$ (сотни миллиардов)                                 |
| Память (на примере LLaMA-7B)    | ~56 GB (fp32), ~28 GB (fp16) + градиенты + optimizer states |
| Optimizer states (Adam)         | Ещё ~56 GB (m, v)                                           |
| Итого для 7B                    | ~112–168 GB GPU memory                                      |
| Время (одна эпоха)              | Дни–недели на A100                                          |

### Достоинства и недостатки

**Плюсы:**
- Максимальная гибкость — может адаптироваться к любым сдвигам распределения
- Потенциально наилучшее качество на целевой задаче

**Минусы:**
- Огромные вычислительные затраты
- Нужно хранить отдельную копию модели для каждого датасета
- Риск **катастрофического забывания** (catastrophic forgetting)
- Требует больших GPU-кластеров

### Когда использовать

- Когда есть ресурсы (кластер A100/H100)
- Когда целевой датасет достаточно большой
- Когда нужно глубоко изменить поведение модели

## 2. Supervised Fine-Tuning (SFT)

**Суть:** Дообучение LLM на парах (вход → ожидаемый ответ) с teacher forcing.

### Формальное определение

Дано: размеченный датасет $\mathcal{D} = \{(x^{(i)}, y^{(i)})\}_{i=1}^N$.

Минимизируем negative log-likelihood:

$$
\mathcal{L}_{\text{SFT}}(\theta) = -\sum_{i=1}^{N} \log P_\theta(y^{(i)} \mid x^{(i)}) = -\sum_{i=1}^{N} \sum_{t=1}^{T} \log P_\theta(y_t^{(i)} \mid y_{<t}^{(i)}, x^{(i)})
$$

### Teacher Forcing

На каждом шаге декодирования модели подаётся **правильный** предыдущий токен из обучающего примера, а не её собственное предсказание:

$$
y_t \sim P_\theta(\cdot \mid y_{<t}^{\text{(ground-truth)}}, x)
$$

Это ускоряет сходимость, но создаёт **exposure bias** — на инференсе модель использует свои (возможно, ошибочные) предсказания.

### Стандартный пайплайн

```
[[DL 36 - GPT|Pretrained LLM]] → SFT on task data → (optional) [[DL 39 - Preference Tuning и RLHF|Preference tuning]] → Deploy
```

### Роль SFT

- Первый этап обучения под конкретную задачу
- Позволяет модели выучить формат и стиль ответов
- База для последующего [[DL 39 - Preference Tuning и RLHF|RLHF/DPO]]

## 3. Instruction Tuning

**Суть:** Дообучение LLM на смеси инструкций (instruction → response) для улучшения способности следовать указаниям.

### Чем отличается от SFT

| Аспект | SFT | Instruction Tuning |
|---|---|---|
| Формат данных | (вход→выход) | (инструкция→ответ) |
| Датасет | Монолитный | Мульти-задачный, перемешанный |
| Цель | Одна конкретная задача | Обобщение на невидимые инструкции |
| Масштаб | Несколько тысяч примеров | Десятки–сотни тысяч примеров |

### Ключевые датасеты

- **FLAN** (Google) — 1.8K+ задач, сформулированных как инструкции
- **Self-Instruct** — генерация инструкций самой LLM
- **Alpaca** (Stanford) — 52K инструкций, сгенерированных GPT-3.5
- **ShareGPT** — реальные диалоги пользователей с ChatGPT
- **OpenAssistant** — открытый датасет с человеческими ответами

### Техники Instruction Tuning

1. **Template-based:** Все задачи переформулируются в единый шаблон: `"Instruction: {instr}\nInput: {input}\nOutput:"`
2. **Multi-task mixing:** Задачи перемешиваются с весами, обратно пропорциональными размеру датасета
3. **Balanced sampling:** Чтобы избежать перекоса в сторону больших датасетов

### Результаты

- Instruction-tuned модели (InstructGPT, Alpaca, Vicuna) значительно лучше следуют инструкциям
- Улучшается zero-shot обобщение на невидимые задачи
- Модели учатся понимать намерения пользователя (instruction following)

### Проблемы

- **[[DL 41 - Catastrophic Forgetting|Catastrophic forgetting]]** инструкций при дальнейшем обучении
- **Label noise** — не все инструкции одинаково качественные
- **Diversity vs Quality** — трудно собрать датасет, покрывающий все возможные инструкции

## 4. Parameter-Efficient Fine-Tuning (PEFT)

### Мотивация

Full fine-tuning для LLM (175B параметров) требует ~1.4 TB GPU памяти только для хранения весов в fp32. PEFT решает эту проблему, обучая только небольшое количество дополнительных параметров.

### Общая схема

Предобученные веса $\phi$ **замораживаются**.
Обучается только небольшой набор дополнительных параметров $\psi$, где $|\psi| \ll |\phi|$:

$$
P_\theta(y \mid x) = P_{\phi, \psi}(y \mid x), \quad \theta = \{\phi \text{ (frozen)}, \psi \text{ (trainable)}\}
$$

### Сравнение методов PEFT

| Метод | Обучаемых параметров (7B) | Дополнительная память | Качество vs FFT |
|---|---|---|---|
| Full FT | 7B (100%) | ~112 GB | Эталон |
| Adapters (Houlsby) | ~3–5% | ~6 GB | 95–99% |
| LoRA | ~0.1–1% | ~1–2 GB | 98–100% |
| Prefix Tuning | ~0.01–0.1% | < 1 GB | 90–98% |
| Prompt Tuning | ~0.01% | < 1 GB | 85–95% |

## 5. Adapters (Houlsby et al., 2019)

### Архитектура

В каждый Transformer-блок добавляются **bottleneck-слои** — два последовательных linear слоя с non-linearity между ними:

```
Input → LayerNorm → Down-project → ReLU → Up-project → Residual (+ Input) → Output
```

$$
h \in \mathbb{R}^d \quad \rightarrow \quad h' = W_{\text{up}} \cdot \text{ReLU}(W_{\text{down}} \cdot h) + h
$$

где $W_{\text{down}} \in \mathbb{R}^{r \times d}$, $W_{\text{up}} \in \mathbb{R}^{d \times r}$, $r \ll d$.

### Варианты размещения

1. **После attention и FFN** (Houlsby): два адаптера на блок
2. **Только после FFN** (Pfeiffer): один адаптер на блок, меньше параметров

### Достоинства

- Высокое качество (близко к FFT)
- Возможность переключаться между задачами (меняем адаптер)
- Не меняет [[DL 42 - Инференс LLM|latency на инференсе]] (если адаптеры можно объединить с weights)

### Недостатки

- Добавляет слои, увеличивающие глубину — последовательное вычисление
- Не все имплементации позволяют merge

## 6. LoRA (Low-Rank Adaptation) — Hu et al., 2021

### Идея

Изменение весов $\Delta W$ имеет низкий ранг (intrinsic rank). Поэтому аппроксимируем:

$$
\Delta W = BA, \quad \text{где } B \in \mathbb{R}^{d \times r}, A \in \mathbb{R}^{r \times k}, r \ll \min(d, k)
$$

Тогда:

$$
h' = W_0 x + \Delta W x = W_0 x + BAx
$$

$$
W_0 \in \mathbb{R}^{d \times k}, \quad B \in \mathbb{R}^{d \times r}, \quad A \in \mathbb{R}^{r \times k}
$$

### Обучение

- $W_0$ заморожен, $A$ и $B$ обучаются
- Инициализация: $A \sim \mathcal{N}(0, \sigma^2)$, $B = 0$ (в начале $\Delta W = 0$)
- Scaling: $\frac{\alpha}{r}$ — гиперпараметр для амплитуды обновления

### Применение к Transformer

Обычно LoRA применяется к матрицам Query ($W_q$) и Value ($W_v$) в attention:

$$
\text{Attention}(Q, K, V) = \text{softmax}\left(\frac{QK^T}{\sqrt{d_k}}\right)V
$$

где $Q = (W_0^q + B_qA_q)X$, $K = (W_0^k + B_kA_k)X$, и т.д.

### Сравнение LoRA vs Adapters

| Свойство | LoRA | Adapters |
|---|---|---|
| Изменяет исходный слой | Да (добавка к весам) | Нет (новые слои) |
| Mergeable | Да ($W = W_0 + BA$) | Да (с fusion) |
| Inference latency | 0 (после merge) | Есть без merge |
| Ранг | Гиперпараметр $r$ | Размер bottleneck |
| Типичный $r$ | 4–32 | 64–512 |

### Достоинства LoRA

- **Никакого дополнительного latency** на инференсе (веса сливаются)
- **Экономия памяти**: для 7B модели LoRA с $r=8$ занимает ~16 MB
- **Быстрое переключение** между задачами: храним только LoRA-веса
- Качество сопоставимо с FFT

## 7. Prefix Tuning (Li & Liang, 2021)

### Идея

Добавляем **специальные виртуальные токены** (prefix) к каждому Transformer-слою во входной последовательности. Эти токены обучаются, а исходные веса заморожены.

### Формально

Обычный Transformer: $h_t = \text{Transformer}(x_1, \dots, x_t)$

Prefix Tuning:

$$
z_t = 
\begin{cases}
P_\theta[t], & t < l_p \\
x_{t - l_p}, & t \geq l_p
\end{cases}
$$

где $P_\theta \in \mathbb{R}^{l_p \times d}$ — обучаемый префикс длины $l_p$.

### Ключевой трюк

Напрямую обучать $P_\theta$ нестабильно. Используется **reparametrization**:

$$
P_\theta[t] = \text{MLP}_\theta(h_t'), \quad h_t' \in \mathbb{R}^{d'}, \quad d' \ll d
$$

На инференсе MLP пересчитывается в явный префикс.

### Особенности

- Не меняет архитектуру модели
- Требуется разная длина префикса для разных задач
- Качество ниже LoRA на сложных задачах

## 8. Prompt Tuning (Lester et al., 2021)

### Упрощение Prefix Tuning

**Только на входном слое** (embedding layer) добавляются обучаемые "soft prompts":

$$
x' = [P_\theta, x_1, x_2, \dots, x_n]
$$

где $P_\theta \in \mathbb{R}^{l_p \times d}$ — обучаемый prompt длины $l_p$, $x_i$ — реальные токены.

### Отличие от Prefix Tuning

| Аспект | Prefix Tuning | Prompt Tuning |
|---|---|---|
| Слои | Все слои | Только embedding |
| Параметров | Больше | Меньше ($l_p \times d$) |
| Гибкость | Выше | Ниже |
| Качество | Выше | Ниже |
| Простота | Сложнее | Проще |

### Пример

Для $l_p = 20$, $d = 4096$ (LLaMA-7B):
- Prompt Tuning: $20 \times 4096 = 81,920$ параметров (~0.001%)
- LoRA (r=8, Q+V): $2 \times 2 \times 4096 \times 8 \times 32 = 4,194,304$ параметров (~0.06%)

## 10. Практические рекомендации

| Сценарий | Рекомендуемый метод |
|---|---|
| Есть много GPU, нужен максимум качества | Full FT (SFT) → RLHF/DPO |
| Ограниченные GPU, но высокое качество | LoRA (r=8–32 на Q+V) |
| Очень большая модель (175B+) | LoRA + QLoRA (INT4) |
| Быстрый эксперимент | Prompt Tuning (short prefix) |
| Много задач, быстрое переключение | LoRA (общий base, разные LoRA weights) |
| Instruction Tuning | Full FT или LoRA на инструктивном датасете |

## 11. Ключевые термины

- **Fine-tuning** — дообучение предобученной модели на целевых данных
- **Supervised Fine-Tuning (SFT)** — дообучение c teacher forcing на парах (вход→выход)
- **Instruction Tuning** — SFT на датасете инструкций для улучшения instruction following
- **PEFT (Parameter-Efficient Fine-Tuning)** — группа методов, обучающих только малую часть параметров
- **Adapter** — bottleneck-слой, вставленный в Transformer
- **LoRA** — низкоранговая аппроксимация обновления весов $\Delta W = BA$
- **Prefix Tuning** — обучаемые виртуальные токены на всех слоях
- **Prompt Tuning** — обучаемые soft prompts на входном слое
